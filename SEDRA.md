# Sedra on rusty-kaspa

This repository is a Sedra node built on [rusty-kaspa](https://github.com/kaspanet/rusty-kaspa) **v1.0.1**
(`fcd9c28f`), the Rust node of Kaspa. Sedra's own node, `sedrad`, is a copy of Kaspa's Go node v0.12.15; this project
moves Sedra to the Rust codebase. It is part of the
[Sedra merged-mining project](https://github.com/necatgit/sedra-merged-mining) (public from late November 2026); the reasoning is in its
`research/0004-rust-path.md`.

**Status: release 0.1.0 (2026-11-14), the same consensus rules as sedrad v2.0.0. Merged mining is not part of it.**

## Branches

- `main`: releases only; each release is a merge commit with a signed tag `sedra-vX.Y.Z`.
- `dev`: Sedra changes, integrated. Every change is listed below.
- Feature branches off `dev`, for example `m10-auxpow` (merged mining, not in a release yet).
- Unmodified upstream rusty-kaspa v1.0.1 is the tag `v1.0.1`.

## Goal of Step 1

A node with exactly the same consensus rules as Sedra mainnet today (sedrad v2.0.0, `4a1153d`), able to sync and run
next to the existing Go nodes. No fork. Progress is tracked as milestones M1-M9 in the project repository.

**Test results for M1** (2026-11-05, Ubuntu 24.04, rustc 1.99.1, `cargo test --release --no-fail-fast --workspace --exclude kaspa-wasm --exclude kaspa-wallet-pskt`):
unmodified v1.0.1: 112 suites, 498 passed, 1 failed, 25 ignored. With M1: 112 suites, 499 passed, 1 failed, 25 ignored.
The one failure on both is `kaspa-perf-monitor::monitor_works`, a timing-dependent test. The extra passing test is the
Sedra genesis test. On the test VM (Ubuntu 26.04, GCC 15, own NVMe), M1 gives 112 suites, 500 passed, 0 failed,
25 ignored: identical per suite, and `monitor_works` passes there.

**v2.0.0 relaunch rules (M6):** `difficulty_reset_*` and `treasury_allocation_*` in `Params` (mainnet only),
applied in `DualWindowManager::calculate_difficulty_bits` and `CoinbaseManager::expected_coinbase_transaction`.
Tests in `consensus/src/processes/sedra_relaunch_rules_test.rs` (expected values from sedrad's own code) and
`sedra_difficulty_reset_wiring_test` (running consensus).

Not taken from upstream: `48b63582` (every proof level not rooted at genesis must have a selected tip with blue score
>= 2M). The real mainnet proof built by sedrad fails it (level 13: 2037 headers, blue score 1998 < 2000), so the Rust
node could not sync from any Go node. Both pruning-proof changes above were tested with a fresh sync from a local sedrad
on 2026-11-06.

Not taken from upstream: lowering the overall P2P message limit from 1 GB to 256 MB. Protocol v5 sends the pruning
point proof as one message, and Sedra's may be close to that size; to be measured first.

Dependency updates from `cargo audit` (28 → 10 advisories, none of the remaining reachable from the network in the node
as run with UPnP disabled) were merged together with the hardening changes on 2026-11-06 (full test run: 517 passed,
0 failed, 25 ignored).

From the back-port list (#29), the must-fix and should items were merged first. The optional back-ports below were
merged after the seven-day run (M9), so that the run measured one version (tested on their branch: full suite 518
passed, 0 failed):

|---|---|---|

| File-descriptor budget for the UTXO index without i32 overflow | `8ae55970` | `sedra_utxo_index_fd_share_does_not_overflow` |

## Releases

`sedra_release()` in `core/src/kaspad_env.rs` holds the release of this node (`0.1.0` for step 1). `kaspad --version`
and the startup log show it with the upstream base and the commit, e.g. `0.1.0 (rusty-kaspa v1.0.1, commit
9cb74efc1234)`. The P2P user agent stays the upstream `kaspad:1.0.1`, so the handshake with the Go nodes is unchanged.

Releases are built reproducibly (`contrib/reproducible/`, pinned Rust image and Debian snapshot; `rust-toolchain.toml` pins
rustc 1.99.1) and verified by rebuilding: see `docs/RELEASE.md`. The upstream release workflow
(`.github/workflows/deploy.yaml`) is removed: it built unverifiable binaries under Kaspa's names on every GitHub release.
The upstream README is kept as `docs/README-rusty-kaspa.md`. `utils/build.rs` also embeds the commit when HEAD is detached (a checked-out release tag); upstream embedded none in that case.

## Building

On Linux with Rust (rustup), clang, protoc, cmake and the usual build tools
(`build-essential clang llvm libclang-dev pkg-config libssl-dev protobuf-compiler cmake`):

```
cargo build --release --bin kaspad
cargo test --release --no-fail-fast --workspace --exclude kaspa-wasm --exclude kaspa-wallet-pskt
```

Tested on Ubuntu 24.04 (GCC 13) and Ubuntu 26.04 (GCC 15), both with rustc 1.99.1.

**GCC 15 note:** RocksDB 8.10, which this version uses, does not include `<cstdint>` itself and fails to compile with
GCC 15. `.cargo/config.toml` adds `-include cstdint` to `CXXFLAGS` automatically. If you set your own `CXXFLAGS`,
include `-include cstdint` in it.
