# Sedra on rusty-kaspa

This repository is a Sedra node built on [rusty-kaspa](https://github.com/kaspanet/rusty-kaspa) **v1.0.1**
(`fcd9c28f`), the Rust node of Kaspa. Sedra's own node, `sedrad`, is a copy of Kaspa's Go node v0.12.15; this project
moves Sedra to the Rust codebase. It is part of the
[Sedra merged-mining project](https://github.com/necatgit/sedra-merged-mining); the reasoning is in its
`research/0004-rust-path.md`.

**Status: work in progress. Not for mainnet use.**

## Branches

- `main`: unmodified upstream rusty-kaspa v1.0.1, as a reference point.
- `dev`: Sedra changes. Every change is listed below.

## Goal of Step 1

A node with exactly the same consensus rules as Sedra mainnet today (sedrad v2.0.0, `4a1153d`), able to sync and run
next to the existing Go nodes. No fork. Progress is tracked as milestones M1-M9 in the project repository.

## Changes from upstream v1.0.1

| Area | Change | Source of the Sedra values |
|---|---|---|
| Mainnet genesis | Sedra's genesis block (DAA score 0, empty UTXO set, payload `sedra-mainnet`), hash `7c380ae6…5ffa` | sedrad `domain/dagconfig/genesis.go` |
| Devnet genesis | Identical to the mainnet genesis, as in sedrad | same |
| Network names | `sedra-mainnet`, `sedra-testnet-10`, ... (the P2P handshake rejects mismatches) | sedrad `params.go` |
| Address prefixes | `sedra`, `sedratest`, `sedrasim`, `sedradev` | sedrad `util/address.go` |
| Ports | P2P 22111 / RPC 22110 on mainnet (testnet 222xx, simnet 225xx, devnet 226xx) | sedrad `params.go` |
| DNS seeders | `sedra-seed-1/2/3.sedracoin.com`; none on testnet | sedrad `params.go` |
| Subsidy table | Sedra's 192 monthly entries, padded with zeros to the upstream table size (same result: Go clamps to its last entry, which is 0) | sedrad `coinbasemanager.go` |
| Later Kaspa features | `crescendo_activation = never` on every network: Sedra runs the pre-Crescendo rules of kaspad v0.12.15 | — |
| Minimum difficulty window | 2641 instead of 150: the Go node uses genesis difficulty until the full window exists | sedrad `difficultymanager.go` |
| P2P protocol v5 | Accepted on every network (Sedra's Go nodes speak only v5) | — |
| Tests | Address vectors replaced with values generated by sedrad's Go code (347 wallet and script vectors re-encoded with sedrad's bech32); subsidy test uses values from sedrad's Go table; explicit genesis-hash test | sedrad v2.0.0 |
| Test fixes | `bounded_merge_depth_test`: forces block level 0, because its helper only sets level-0 parents and one synthetic block gets level 3 with Sedra's genesis data. JSON reference-DAG tests: use Kaspa's devnet genesis payload, because that data was generated by Kaspa's Go node on Kaspa's devnet | — |

**Test results for M1** (2026-11-05, Ubuntu 24.04, rustc 1.99.1, `cargo test --release --no-fail-fast --workspace --exclude kaspa-wasm --exclude kaspa-wallet-pskt`):
unmodified v1.0.1: 112 suites, 498 passed, 1 failed, 25 ignored. With M1: 112 suites, 499 passed, 1 failed, 25 ignored.
The one failure on both is `kaspa-perf-monitor::monitor_works`, a timing-dependent test. The extra passing test is the
Sedra genesis test.

**Not yet done:** the v2.0.0 relaunch rules (difficulty reset and treasury outputs, milestone M6); the two hardcoded
fallback peers from sedrad; renaming binaries, crates and user-facing texts (the binary is still called `kaspad`);
removing Kaspa-specific RPC data (mainnet timestamp samples).

## Building

On Linux (Ubuntu 24.04 tested) with Rust, clang, protoc and the usual build tools:

```
cargo build --release --bin kaspad
cargo test --release -p kaspa-consensus-core -p kaspa-addresses -p kaspa-consensus -p kaspa-p2p-flows
```
